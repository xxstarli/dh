## 4. 数据结构

|模型|主要字段与规则|
|---|---|
|Category|id、name、sort_order、created_at、updated_at；名称不唯一|
|Site|id、category_id、name、url、description、icon_type、icon_url、sort_order及时间戳；URL/名称不唯一|
|Settings|单例；site_name、site_logo、admin_password_hash及时间戳|
|AdminSession|哈希后的随机token作为id；expires_at、created_at|

Category与Site为一对多。Site必须属于存在的分类，删除关系为RESTRICT。分类排序及分类内网站排序有索引；修改所属分类追加到目标末尾，未换分类保留顺序。没有增加其他产品业务模型。

## 5. 已完成功能

首页从数据库读取Settings、分类和网站；普通模式隐藏空分类。PC五列、4/3/2列响应式、固定卡片宽度、不满一行左对齐。实时搜索名称/说明/域名，忽略大小写和首尾空格；整卡在安全新标签页打开。

管理验证后留在原首页。支持分类和网站增删改、分类拖拽、分类内网站拖拽，非空分类禁止删除，跨分类通过编辑完成。排序立即持久化，失败回滚。

自动Favicon成功显示预览；失败默认图标不阻断保存。支持PNG/JPEG/WebP上传和恢复自动，自定义图标不会被自动覆盖。

实现必填/长度/URL校验、保存和上传失败保留输入、删除确认、加载锁、空状态、网络错误、会话失效后重新登录并保留表单。弹窗焦点限制、Esc/关闭/取消、菜单视口避让和减少动效偏好均已处理。

三张设计图经过实际浏览器截图对照。尺寸、留白、字号、卡片、弹窗和管理模式按确认稿落实；示例Logo未硬编码，可选主题按钮未实现。详细对照在根目录design-qa.md。

## 6. 数据持久化

默认数据库为storage/navigation.db，图标位于storage/icons，均独立于.next构建目录。上传图片实际解码、限制2MB及1600万像素，重新编码为最大256px的WebP，以内容哈希命名并通过/api/icons读取。

正式库保持0分类、0网站，方便直接录入自己的数据。浏览器验收使用storage/e2e，业务测试使用独立unit目录；测试不会清空正式库。

已实测：页面刷新、完整退出再开浏览器、重新构建、两次生产服务启动后数据和图片保留。远端主机升级部署尚未执行。

## 7. 管理鉴权

服务端bcrypt cost 12校验，随机256位Session Token，数据库仅保存SHA-256摘要。Cookie为HttpOnly、SameSite=Strict，APP_ORIGIN配置HTTPS时启用Secure。会话默认12小时，退出删除服务端Session。

所有写API、上传和图标抓取均先校验管理员会话；写请求检查Origin。未授权401、错误来源403。登录有限流。没有前端硬编码生产密码，不把会话放在localStorage。

SSRF抓取只允许HTTP/HTTPS和80/443端口，拒绝内网/回环/Metadata/保留地址，DNS解析结果固定到连接，重定向每跳重新验证；限制6秒、2MB和3次重定向。失败安全降级。

当前随机初始密码仅保存在本机storage/首次管理密码.txt，已被Git忽略；本报告不包含真实密码。修改密码使用README中的admin:password工具。

## 8. 本地运行

**当前目录已经安装和初始化，不要重新覆盖.env。** 当前正式服务已启动。

PowerShell再次启动：

~~~powershell
cd "E:\Star\小码力\导航站"
.\start.ps1 -Production
~~~

开发模式使用：

~~~powershell
.\start.ps1
~~~

首次在另一台机器安装，使用Node.js 24和pnpm 11：

~~~powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
pnpm admin:password
~~~

将生成的哈希填入.env的ADMIN_PASSWORD_HASH并配置APP_ORIGIN，然后：

~~~powershell
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm build
pnpm start
~~~

已有数据库修改密码：pnpm admin:password --apply。它会使现有管理会话失效。

当前主流程检查命令：

~~~powershell
pnpm lint
pnpm typecheck
pnpm build
pnpm test
pnpm test:e2e
node tests/restart.mjs
~~~

浏览器测试需要安装Chrome、Edge并释放3100端口；重启测试需要先完成build和e2e，使用3101。补充脚本supplemental.mjs是有验收数据前提的记录脚本：需要3100测试服务以及本次“重启持久化验收”分类中的“持久化网站”“Bing”，不属于无前置条件的常规测试命令。

## 9. 环境变量

|变量|是否必填|用途|
|---|---|---|
|DATABASE_URL|是|SQLite数据库位置；相对路径以prisma目录为基准|
|APP_ORIGIN|是|唯一浏览器来源，包括协议/端口；Origin验证及Secure Cookie|
|ADMIN_PASSWORD_HASH|Seed时必填|bcrypt cost12管理密码哈希，不填明文|
|UPLOAD_DIR|否|持久图标目录，默认storage/icons|
|SITE_NAME|否|首次Seed站点名称，默认“我的导航”|
|SITE_LOGO|否|首次Seed可选Logo，空值默认图标|
|SESSION_HOURS|否|Session小时数，1–24，默认12|
|NEXT_BUILD_DIR|仅测试可选|测试构建隔离为.next-e2e，日常不设置|

.env.example不含Secret。已有Settings的Seed不会覆盖现有设置。

## 10. 部署建议

按本项目的SQLite和本地图标结构，采用单台服务器、单个常驻Node.js进程及持久磁盘。前置HTTPS反向代理，APP_ORIGIN使用实际域名。数据库和图标目录固定在应用发布目录外，部署仅替换源码/构建产物。

部署流程为安装依赖、生成ORM、迁移、Seed、build、start。备份时暂停写入或服务，同时备份数据库、图标和独立安全保存的环境配置。具体路径示例见README。

当前未发布到远端，也没有设置公网域名。无状态临时磁盘平台不适用于现有存储方案。
