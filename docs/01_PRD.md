# 个人导航网站 V1 PRD

> 文档版本：V1.0  
> 产品定位：个人自用网址导航  
> 开发目标：简洁、快速、低维护成本，不设计过多复杂功能  
> 本文档为 V1 开发单一事实源（SSOT）。如 UI 示例与本文档存在冲突，以本文档业务规则为准。

---

# 1. 产品概述

## 1.1 产品名称

暂定：**我的导航**

后续可修改站点名称及 Logo，不影响 V1 核心业务。

## 1.2 产品定位

一个用于个人日常使用的网址导航网站。

用户进入首页后，可以直接看到所有分类，以及每个分类下的全部网站卡片，无需进入二级页面，也不需要通过左侧菜单切换分类。

核心使用场景：

1. 快速找到常用网站。
2. 点击网站卡片直接访问目标网站。
3. 通过搜索快速定位网站。
4. 进入管理模式后直接在首页维护分类和网站。
5. 通过拖拽调整分类及网站顺序。

## 1.3 产品原则

V1 坚持以下原则：

- 简洁优先。
- 首页即全部内容。
- 所见即所得管理。
- 不做独立复杂后台。
- 不做多用户体系。
- 不做资讯、排行、推荐等门户功能。
- 不为了未来可能用到的需求提前增加复杂度。
- 不允许开发过程中自行扩展未定义功能。

# 2. V1 产品目标

## 2.1 核心目标

实现一个完整可用的个人导航网站，满足：

- 分类可自定义添加。
- 首页展示全部分类。
- 每个分类直接展示全部网站。
- PC 端每行最多 5 个网站卡片。
- 支持搜索网站。
- 支持网站新增、编辑、删除。
- 支持分类新增、编辑、删除。
- 支持分类拖拽排序。
- 支持分类内网站拖拽排序。
- 支持管理密码进入管理模式。
- 所有管理操作直接在首页完成。
- 数据刷新页面后仍然存在。

## 2.2 成功标准

用户可以在不进入任何复杂后台的情况下完成：

> 打开首页 → 找到网站 → 点击访问

以及：

> 首页 → 管理 → 添加/编辑/删除/排序 → 完成管理

# 5. 首页

## 5.1 页面目标

首页用于集中展示全部网站入口。

进入网站后，用户无需切换分类，也无需进入二级页面，即可看到所有分类及各分类下的网站。

## 5.2 页面结构

首页由以下区域组成：

1. 顶部导航区
2. 分类内容区
3. 网站卡片区

### 顶部导航区

包含：

- 网站 Logo / 名称
- 搜索框
- 管理入口

示意：

```text
我的导航            搜索网站...                    管理
```

# 6. 分类展示规则

## 6.1 分类层级

V1 仅支持：

> 一级分类

不支持二级分类。

## 6.2 分类展示

首页按照分类排序值，从上到下展示全部分类。

例如：

```text
常用

[ ChatGPT ] [ GitHub ] [ 飞书 ] [ Notion ] [ Gmail ]


AI 工具

[ Claude ] [ Gemini ] [ 即梦 ] [ Perplexity ]


开发工具

[ GitHub ] [ Vercel ] [ Supabase ]
```

## 6.3 分类标题

分类标题显示：

- 分类名称
- 当前网站数量

例如：

```text
AI 工具  5
```

网站数量使用弱化视觉展示。

## 6.4 空分类

### 普通浏览模式

分类中没有网站时：

> 不显示该分类。

### 管理模式

空分类仍然显示：

```text
AI 工具  0

暂无网站

＋ 添加网站
```

## 6.5 分类顺序

按照 `sort_order` 从小到大展示。

管理模式下支持拖拽修改顺序。

拖拽完成后立即持久化。

# 7. 网站卡片

## 7.1 展示内容

网站卡片包含：

- 网站图标
- 网站名称
- 网站说明

示例：

```text
┌──────────────────────┐
│  ● ChatGPT           │
│    AI 对话助手        │
└──────────────────────┘
```

## 7.2 网站说明为空

如果没有填写网站说明：

> 第二行显示网站域名。

例如：

```text
ChatGPT
chatgpt.com
```

## 7.3 点击行为

普通浏览模式：

> 点击整张网站卡片，在新标签页打开网站。

建议实现：

```text
target="_blank"
```

并增加必要安全属性。

## 7.4 Hover

网站卡片 Hover 时：

- 轻微上浮
- 边框或阴影轻微加强
- 鼠标变为 pointer

动画保持轻量，建议 150～200ms。

# 8. 网站卡片布局

## 8.1 PC 端

PC 常规页面宽度：

> 每行最多 5 个网站卡片。

规则：

- 1～5 个：1 行
- 6～10 个：2 行
- 11～15 个：3 行
- 依此类推

示例：

```text
[ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ]
[ 6 ] [ 7 ] [ 8 ]
```

第二行不足 5 个时：

> 从左向右排列。

禁止：

- 自动居中
- 自动放大卡片填满整行

同一页面中网站卡片：

- 宽度统一
- 高度统一
- 横向间距统一
- 纵向间距统一

## 8.2 响应式

当页面宽度不足时允许自动减少列数。

建议：

- 常规 PC：5 列
- 中等屏幕：4 列
- 较小屏幕：3 列
- 手机：2 列

重点要求：

> 常规 PC 页面默认保持 5 列。

# 9. 网站搜索

## 9.1 搜索框

顶部显示：

> 搜索网站...

## 9.2 搜索范围

支持匹配：

- 网站名称
- 网站说明
- 网站域名

## 9.3 搜索方式

用户输入关键词后实时筛选。

不需要点击搜索按钮。

## 9.4 搜索结果展示

搜索结果继续按原分类展示。

某分类没有匹配网站时：

> 不显示该分类。

## 9.5 无结果

显示：

> 没有找到相关网站

同时提供：

> 清除搜索

## 9.6 搜索不改变排序

搜索仅做过滤，不修改：

- 分类排序
- 网站排序

清除搜索后恢复完整首页。

# 10. 管理入口

## 10.1 普通状态

首页右上角显示：

> 管理

## 10.2 点击管理

点击后打开管理密码验证弹窗。

V1 为个人自用工具，不设计完整账号系统。

# 11. 管理身份验证

## 11.1 验证字段

仅包含：

> 管理密码

## 11.2 验证成功

进入管理模式。

## 11.3 验证失败

提示：

> 管理密码错误，请重新输入

不关闭弹窗。

## 11.4 管理状态

管理验证成功后，在当前会话中保持管理状态。

点击“完成管理”后退出。

不设计用户中心、修改密码后台等复杂页面。

---

# 12. 管理模式

## 12.1 核心原则

管理模式与普通首页使用：

> 同一个页面。

不跳转独立管理后台。

## 12.2 进入后的变化

顶部：

```text
管理
```

变为：

```text
完成管理
```

页面增加轻量提示：

> 当前处于管理模式，可添加、编辑、删除和拖动排序分类或网站。

分类增加：

- 拖动入口
- 编辑
- 删除
- 添加网站

网站增加：

- 拖动入口
- 编辑
- 删除

页面底部增加：

- 添加分类

## 12.3 管理模式下的网站点击

管理模式下，不建议点击卡片主体直接跳转网站。

网站更多菜单可包含：

- 编辑
- 删除
- 打开网站（可选）

如果实现“打开网站”，仍需新标签页打开。

# 13. 分类管理

## 13.1 添加分类

入口：

> ＋ 添加分类

字段：

- 分类名称（必填）

保存后：

> 新分类添加到分类列表最后。

## 13.2 编辑分类

字段：

- 分类名称

保存后首页立即更新。

## 13.3 删除分类

### 空分类

允许删除。

确认提示：

> 确定删除“XXX”分类吗？

### 非空分类

禁止直接删除。

提示：

> 当前分类下还有 X 个网站，请先移动或删除这些网站。

V1 不允许：

> 删除分类时级联删除全部网站。

## 13.4 分类拖拽排序

管理模式下支持上下拖动分类。

拖拽松开：

> 立即保存排序。

保存失败：

- 恢复原顺序
- 提示操作失败

# 14. 添加 / 编辑网站

## 14.1 弹窗形式

添加和编辑网站均使用弹窗。

不跳转新页面。

## 14.2 字段

### 网站名称

必填。

建议最大长度：

> 30 字符

### 网站地址

必填。

支持：

```text
https://example.com
http://example.com
```

如果输入：

```text
example.com
```

系统自动补：

```text
https://
```

转换为：

```text
https://example.com
```

保存时校验 URL 格式。

### 网站图标

选填。

支持：

1. 自动获取网站 Favicon
2. 手动上传图片

推荐支持：

- PNG
- JPG / JPEG
- WebP

建议上传大小：

> ≤ 2MB

显示优先级：

> 手动上传图标 ＞ 自动获取图标 ＞ 默认网站图标

自动获取失败：

> 不阻止网站保存。

编辑时可提供：

> 恢复自动获取

### 网站说明

选填。

建议最大长度：

> 50 字符

卡片中单行显示，超出省略。

### 所属分类

必填。

通过下拉选择已有分类。

# 15. 添加网站业务规则

## 15.1 从分类中添加

管理模式下，每个分类提供：

> ＋ 添加网站

点击后：

> 所属分类默认选中当前分类。

用户仍然可以修改。

## 15.2 新增位置

新增网站保存成功后：

> 默认添加到所属分类最后。

例如当前有：

```text
1 2 3 4 5
```

新增后：

```text
1 2 3 4 5
6
```

## 15.3 URL 重复

V1 允许相同 URL 重复添加。

例如 GitHub 可以同时出现在：

- 常用
- 开发工具

不做强制唯一校验。

---

# 16. 编辑网站业务规则

编辑时带入已有数据。

支持修改：

- 名称
- 地址
- 图标
- 说明
- 所属分类

## 16.1 修改所属分类

如果从分类 A 修改到分类 B：

- 从分类 A 移除
- 添加到分类 B
- 默认排列在分类 B 最后

# 17. 删除网站

点击删除后显示确认：

> 确定删除“XXX”吗？

按钮：

- 取消
- 确认删除

删除后：

- 当前分类网站数量即时更新
- 剩余网站自动按原排序重新排列

# 18. 网站排序

## 18.1 排序范围

> 编辑网站 → 修改所属分类。

## 18.2 保存方式

网站拖拽松开后：

> 立即保存新排序。

保存失败：

- 恢复原顺序
- 提示保存失败

## 19.1 默认行为

```text

  ↓
```

# 21. 操作保存原则

V1 所有修改：

> 独立即时保存。

不设计页面级“保存全部”。

包括：

- 新增分类：保存即生效
- 编辑分类：保存即生效
- 删除分类：确认即生效
- 分类排序：拖拽松开即保存
- 新增网站：保存即生效
- 编辑网站：保存即生效
- 删除网站：确认即生效
- 网站排序：拖拽松开即保存

点击：

> 完成管理

仅退出管理状态，不负责统一保存数据。

- 环境变量
- 简单配置文件

不得为了 Settings 增加复杂后台。

# 24. 非功能要求

## 24.1 性能

由于为个人自用网站且数据量较小：

- 首页加载应快速
- 卡片滚动应流畅
- 拖拽操作无明显卡顿
- 不需要复杂缓存架构

## 24.2 数据持久化

必须保证：

> 页面刷新、浏览器关闭重新打开后，分类、网站及排序仍然存在。

禁止仅使用前端临时状态作为最终数据存储。

## 24.3 安全

至少需要：

- 管理密码不明文存储
- 服务端验证管理权限
- URL 输出做基本安全处理
- 上传文件限制类型和大小
- 防止未授权接口直接执行增删改

## 24.4 响应式

需保证：

- PC 为主要使用端
- 平板可正常使用
- 手机不出现明显布局溢出

不要求为手机重新设计独立页面。

# 25. UI 设计原则

UI 以已确认的设计稿为视觉参考。

整体风格：

- 简洁
- 明亮
- 留白充足
- 浅色背景
- 白色网站卡片
- 轻阴影 / 浅边框
- 统一圆角
- 操作按钮弱化
- 网站图标作为主要视觉识别

开发时应尽量还原：

- 页面布局
- 5 列卡片结构
- 卡片尺寸比例
- 分类间距
- 字号层级
- 圆角
- 边框
- 阴影
- Hover 状态
- 弹窗布局

UI 图中的网站内容属于示例数据。

# 26. 核心流程

## 26.1 浏览网站

```text
进入首页
  ↓
浏览分类 / 搜索
  ↓
找到网站
  ↓
点击网站卡片
  ↓
新标签页打开
```

## 26.2 进入管理

```text
首页
 ↓
点击“管理”
 ↓
输入管理密码
 ↓
验证成功
 ↓
进入管理模式
```

## 26.3 添加网站

```text
管理模式
 ↓
分类下点击“＋ 添加网站”
 ↓
填写网站名称 / 地址
 ↓
自动获取图标
 ↓
可填写说明
 ↓
确认所属分类
 ↓
保存
 ↓
加入该分类末尾
```

## 26.4 编辑网站

```text
管理模式
 ↓
网站更多菜单
 ↓
编辑
 ↓
修改信息
 ↓
保存
 ↓
首页即时更新
```

## 26.5 排序

```text
管理模式
 ↓
拖动分类 / 网站
 ↓
松开
 ↓
立即保存
 ↓
页面保持新顺序
```

## 26.6 完成管理

```text
管理模式
 ↓
点击“完成管理”
 ↓
隐藏所有编辑控件
 ↓
恢复普通浏览模式
```

# 27. 开发验收标准

## 首页

- [ ] 首页正常展示所有非空分类
- [ ] 分类直接展示全部网站
- [ ] 不存在左侧分类栏
- [ ] PC 常规宽度每行最多 5 个网站卡片
- [ ] 不足 5 个时从左向右排列
- [ ] 不自动放大卡片填满一行
- [ ] 网站卡片点击后新标签页打开

## 搜索

- [ ] 支持网站名称搜索
- [ ] 支持网站说明搜索
- [ ] 支持网站域名搜索
- [ ] 搜索实时筛选
- [ ] 无匹配网站的分类自动隐藏
- [ ] 无结果有明确空状态
- [ ] 清除搜索后恢复全部数据

## 分类

- [ ] 支持添加分类
- [ ] 支持编辑分类
- [ ] 空分类可以删除
- [ ] 非空分类不可直接删除
- [ ] 支持分类拖拽排序
- [ ] 分类排序持久化

## 网站

- [ ] 支持添加网站
- [ ] 支持编辑网站
- [ ] 支持删除网站
- [ ] 支持分类内拖拽排序
- [ ] 网站排序持久化
- [ ] 新增网站默认添加到分类末尾
- [ ] 修改所属分类后进入新分类末尾
- [ ] 允许相同 URL 重复添加

## URL

- [ ] URL 为必填
- [ ] 输入 `example.com` 时自动补 `https://`
- [ ] URL 格式错误时阻止保存并提示

## 图标

- [ ] 支持自动获取 Favicon
- [ ] 获取失败不阻止保存
- [ ] 获取失败使用默认图标
- [ ] 支持上传自定义图标
- [ ] 自定义图标优先显示

## 管理模式

- [ ] 管理入口需要密码验证
- [ ] 密码错误有明确提示
- [ ] 验证成功进入同一首页的管理模式
- [ ] 不存在独立复杂后台
- [ ] 管理模式可添加 / 编辑 / 删除 / 排序
- [ ] 点击完成管理恢复普通模式
- [ ] 所有操作即时保存

## 数据

- [ ] 刷新页面后数据仍存在
- [ ] 重新打开网站后数据仍存在
- [ ] 未授权状态不能调用管理接口直接修改数据

## 响应式

- [ ] 常规 PC 默认 5 列
- [ ] 中小屏幕可自动减少列数
- [ ] 手机端无明显溢出

# 28. 开发约束

Codex 开发时必须遵守：

1. 以本文档作为 V1 业务规则单一事实源。
2. 不得自行增加本文档未定义的复杂功能。
3. UI 设计稿作为视觉参考，业务规则冲突时以 PRD 为准。
4. V1 重点是“简洁、稳定、好用”，不是功能数量。
5. 不开发独立复杂后台。
6. 不开发多用户及复杂权限系统。
7. 不开发二级分类。
8. 首页必须直接显示全部分类及网站。
9. PC 常规宽度必须保持每行最多 5 个网站卡片。
10. 所有新增、编辑、删除、排序操作必须持久化。

# 29. V1 完成定义

满足以下条件即可认为 V1 完成：

> 用户可以打开一个简洁的导航首页，直接浏览所有分类及网站；可以搜索网站；点击网站可在新标签页访问；输入管理密码后，可以直接在当前首页新增、编辑、删除和排序分类及网站；退出管理模式后恢复纯导航体验；刷新页面后所有数据和排序保持不变。

V1 达到以上目标后即可进入实际使用，不继续叠加非必要功能。
