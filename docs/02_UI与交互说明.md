# 个人导航网站 V1｜UI 与交互说明

> 文档版本：V1.0  
> 对应 PRD：`01_PRD.md` / 《个人导航网站 V1 PRD》  
> 使用对象：Codex / 前端开发  
> 本文档用于说明 V1 的视觉、布局、交互和页面状态。  
> 如本文档与 PRD 的业务规则冲突，以 PRD 为准。

---

# 1. 设计目标

个人导航网站 V1 的 UI 目标是：

> **简洁、清晰、打开即用。**

整体不是传统门户型导航网站，而是一个轻量的个人网址工作台。

核心设计原则：

- 首页直接展示全部分类和全部网站。
- 不使用左侧分类栏。
- 不使用二级分类。
- 不设计复杂后台。
- PC 为主要使用端。
- 网站卡片是页面核心内容。
- 管理状态与普通状态使用同一首页。
- 通过轻量视觉变化区分浏览与管理，不切换成完全不同的后台界面。
- 不增加与导航无关的信息模块。

# 3. 全局视觉规范

## 3.1 整体风格

整体采用：

- 浅色背景
- 白色卡片
- 轻边框
- 轻阴影
- 中等圆角
- 大面积留白
- 简洁蓝色作为主要交互色
- 页面内容居中
- 不使用大面积高饱和色块

视觉关键词：

> 清爽 / 轻量 / 工具型 / 现代 / 克制

---

## 3.2 页面背景

建议：

```text
页面背景：#F7F9FC ～ #F8FAFC
卡片背景：#FFFFFF
主文字：#172033 ～ #1F2937
次级文字：#7B879B ～ #94A3B8
边框：#E7EBF1 ～ #E5EAF0
主色：#2F80ED ～ #3B82F6
危险色：#EF4444
成功色：#16A34A
```

具体颜色可以根据实际实现微调，但整体需保持接近参考图。

# 4. 全局页面尺寸

## 4.1 内容宽度

PC 页面建议采用：

```text
max-width: 1440px ～ 1480px
```

左右留白根据屏幕宽度自动调整。

常规 PC 屏幕下：

- 内容不贴边
- 左右边距建议约 48～64px
- 大屏幕可适当增加留白

---

## 4.2 顶部导航高度

建议：

```text
72～80px
```

顶部区域保持单行。

---

## 4.3 圆角

推荐：

```text
网站卡片：10～12px
按钮：8～10px
输入框：8～10px
弹窗：18～22px
小菜单：10～12px
```

---

## 4.4 阴影

网站卡片默认不需要明显阴影。

建议：

```text
默认：
浅边框 + 极轻阴影

Hover：
阴影略加强
```

避免厚重悬浮效果。

# 6. 顶部导航

## 6.1 左侧品牌区

包含：

- Logo
- 网站名称
- 可选一句弱化说明

参考图：

```text
[Logo] 我的导航
       高效上网，从这里开始
```

### Logo

建议：

```text
40～44px
```

圆角方形。

### 网站名称

建议：

```text
20～22px
font-weight: 600～700
```

### 副标题

建议：

```text
13～14px
次级灰色
```

副标题不是业务必须项。

如果实际项目不配置副标题，可以直接删除，不影响布局。

---

## 6.2 搜索框

位于顶部中间区域。

建议：

```text
宽度：500～620px
高度：42～46px
```

内容：

```text
🔍 搜索网站...
```

视觉：

- 白色或极浅灰背景
- 浅边框
- 大圆角
- 聚焦时使用主色边框或轻微外发光

### 搜索交互

输入后实时搜索。

无需搜索按钮。

按 `Esc` 可选实现清空或失焦，但不是 V1 必须功能。

---

## 6.3 主题按钮

参考 UI 中存在一个日间/主题图标。

V1 业务并不依赖完整主题系统。

开发处理原则：

- 可以保留一个视觉上的主题按钮。
- 若未实现深色模式，可以暂不显示。
- 不得为了这个按钮扩展复杂主题配置系统。

推荐：

> 如果开发成本低，可实现浅色/深色切换；否则 V1 可直接省略。

该项不属于验收阻塞项。

---

## 6.4 管理按钮

普通模式显示：

> 管理

建议使用主色按钮。

结构：

```text
[⚙ 管理]
```

进入管理模式后替换为：

> 完成管理

结构：

```text
[✓ 完成管理]
```

按钮高度建议：

```text
40～44px
```

# 7. 分类区块

## 7.1 分类间距

分类之间应有明显留白。

建议：

```text
分类标题到卡片：14～16px
分类卡片结束到下一分类标题：28～36px
```

---

## 7.2 分类标题

结构：

```text
[emoji/icon] 分类名称  数量
```

例如：

```text
⭐ 常用  5
🤖 AI 工具  5
💻 开发工具  4
```

分类 Emoji / Icon：

- 可作为视觉装饰
- V1 不要求后台可配置
- 可以根据分类名称使用默认图标
- 也可以只显示分类名称，不影响业务

不要因此增加“分类图标配置”字段。

---

## 7.3 分类名称

建议：

```text
18～20px
font-weight: 600
```

---

## 7.4 网站数量

分类名称后显示数量。

例如：

```text
5
```

建议：

- 12～13px
- 灰蓝浅色背景
- 小型圆形或胶囊
- 视觉弱化

数量根据分类下当前网站数实时计算。

# 8. 网站卡片网格

## 8.1 PC 五列

常规 PC 页面：

> 每行最多 5 个卡片。

推荐 CSS 思路：

```css
grid-template-columns: repeat(5, minmax(0, 1fr));
```

前提是内容区域宽度达到设计要求。

---

## 8.2 卡片间距

建议：

```text
横向 gap：16～20px
纵向 gap：14～18px
```

---

## 8.3 不足五个

必须从左向右排列：

```text
[1] [2] [3]
```

不得：

```text
      [1] [2] [3]
```

也不得让 3 个卡片自动放大占满整行。

---

# 9. 网站卡片 UI

## 9.1 卡片尺寸

五列情况下建议：

```text
高度：80～86px
```

宽度由 Grid 自动计算。

卡片内容水平排列：

```text
[网站图标]  网站名称
            网站说明
```

---

## 9.2 网站图标

建议：

```text
42～48px
```

使用统一的图标容器。

图标应：

- `object-fit: contain`
- 不拉伸
- 不裁切主要内容

---

## 9.3 网站名称

建议：

```text
15～16px
font-weight: 500～600
```

单行显示。

名称过长：

```text
text-overflow: ellipsis
```

---

## 9.4 网站说明

建议：

```text
13～14px
颜色：次级灰
```

只显示一行。

说明为空时显示域名。

---

## 9.5 卡片 Hover

Hover 时：

- 卡片向上移动约 1～2px
- 阴影轻微加强
- 边框颜色略深
- cursor: pointer

不使用放大缩放到影响布局。

推荐：

```text
transition: 150～200ms
```

---

## 9.6 卡片点击

普通模式：

> 整张卡片可点击。

在新标签页打开。

# 11. 首页滚动

首页使用浏览器纵向自然滚动。

禁止：

- 每个分类单独滚动
- 网站卡片横向滚动作为 PC 默认方案
- 无限滚动
- 分页

# 12. 添加 / 编辑网站弹窗

## 12.1 弹窗尺寸

PC 推荐：

```text
宽度：520～620px
```

根据参考 UI，视觉上可以略宽。

高度根据内容自适应。

---

## 12.2 遮罩

弹窗打开后：

- 页面背景加半透明深色遮罩
- 首页仍可辨识
- 禁止背景区域继续操作

建议：

```text
rgba(15, 23, 42, 0.45～0.55)
```

# 16. 网站地址输入框

结构：


# 17. 网站图标区域


## 17.1 图标预览

建议：

```text
96～104px
```

使用圆角方形容器。

---

## 17.2 自动获取成功

显示：

> 已自动获取网站图标

## 17.3 自动获取失败

## 17.4 上传图片

# 20. 弹窗 Footer

底部右侧：

```text
[取消] [保存]
```

保存按钮为主按钮。

建议：

```text

```

---

# 21. 保存交互

点击保存后：

保存按钮变为：

```text
保存中...
```

并禁止重复点击。

保存成功：

- 关闭弹窗
- 首页即时更新

保存失败：

- 弹窗不关闭
- 表单内容保留
- 页面提示错误

---

# 22. 取消 / 关闭

点击：

- 取消
- 右上角 ×

均关闭弹窗。

V1 不需要额外增加：

> 尚未保存，确定关闭吗？

避免增加不必要操作。

# 23. 管理模式 UI

## 23.1 页面基础结构不变

> 不跳转新页面。

原首页继续展示。

只增加：

- 管理提示条
- 分类拖拽控件
- 分类更多菜单
- 网站拖拽控件
- 网站更多菜单
- 添加网站
- 添加分类
- 完成管理按钮

# 24. 管理提示条

```text
ⓘ 当前处于管理模式，可添加、编辑、删除和拖动排序分类或网站。
```

建议：

- 浅蓝背景
- 蓝色文字
- 高度约 48～52px
- 圆角约 8px

# 31. 网站更多菜单

内容：

```text

删除
```

```text

```

若实现：

- 不影响管理状态

# 32. 管理模式网站点击

管理模式下：

> 卡片主体不要直接打开网站。

原因：

避免编辑时误跳转。

普通模式恢复整卡点击。

---

# 33. 网站拖拽排序

只能在：

> 当前分类内部拖拽。

拖动过程中：

- 被拖卡片轻微抬起
- 原位置显示占位
- 目标位置有明确反馈

松开：

- 更新 UI
- 立即保存

保存失败：

- 恢复原顺序
- 提示失败

---

# 34. 分类拖拽排序

分类整体允许上下拖动。

拖动时：

- 整个分类区块作为移动对象
- 显示占位区域

松开即保存。

---

# 35. 添加分类

管理模式页面底部显示：

```text
＋ 添加分类
```

建议：

- 独立描边按钮
- 不使用巨大卡片
- 左对齐

---

# 36. 完成管理

右上角按钮：

> 完成管理

点击后：

- 隐藏管理提示条
- 隐藏所有拖拽手柄
- 隐藏更多菜单
- 隐藏添加网站
- 隐藏添加分类
- 恢复网站卡片整卡点击

因为所有操作均即时保存：

> 完成管理不执行统一保存。

# 42. 键盘与可访问性

V1 至少满足：

- Tab 可以聚焦输入框、按钮和网站卡片。
- Enter 可以激活按钮。
- Esc 可以关闭弹窗。
- 弹窗打开后焦点应限制在弹窗内。
- 图片提供合理 alt。
- 文字与背景对比度可读。
- Hover 不能成为唯一反馈，应同时保留 Focus 状态。

# 43. 动效规范

只使用轻量动效。

建议：

```text
Hover：150～200ms
弹窗出现：150～220ms
菜单出现：100～150ms
```

禁止：

- 大面积缩放
- 弹跳动画
- 长时间渐变动画
- 自动轮播
- 装饰性动态背景

# 45. Codex UI 实现要求

开发过程中需遵守：

1. 先完整阅读 PRD，再阅读本文档。
2. UI 图作为视觉基准，不是业务规则来源。
3. 首页不得添加左侧分类栏。
4. PC 常规宽度必须以 5 列卡片为默认布局。
5. 不足 5 个卡片从左向右排列。
6. 所有分类直接展示其全部网站。
7. 不增加“查看更多”。
8. 不增加分页。
9. 不增加独立管理后台。
10. 管理模式必须在原首页完成。
11. 添加/编辑网站必须使用弹窗。
12. 网站说明必须保持单行，超出省略。
13. 图标自动获取失败不能阻止保存。
14. 普通模式整卡点击，管理模式取消整卡跳转。
15. 拖拽只允许网站在当前分类内部排序。
16. 修改所属分类通过编辑网站弹窗完成。
17. UI 中不要自行增加 PRD 未定义字段。
18. 不为了视觉效果增加复杂动画和组件。
19. 使用真实数据驱动 UI，不将 UI 图中的示例内容硬编码为业务数据。
20. 所有交互状态必须考虑 Loading、Error、Empty。

# 47. 最终体验目标

普通使用时：

> 页面应该像一个非常干净的个人网址首页。

进入管理模式时：

> 页面应该像原首页进入“可编辑状态”，而不是跳进一个后台系统。

用户应当能够：

> 进入首页后几秒内找到网站，并且在需要维护时，用最少操作完成新增、编辑、删除和排序。

这就是 V1 UI 与交互的最终目标。
